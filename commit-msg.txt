docs: remove stale NEXT_PUBLIC_API_BASE_URL guidance that re-breaks login

The reported "Failed to fetch" after #5 was not a code regression: .env is
git-ignored and never touched by `git pull`, so a .env created from an
earlier .env.example (before same-origin routing landed) still had
NEXT_PUBLIC_API_BASE_URL=https://osu.localhost baked in. That value is
read at frontend build time and silently overrides the new empty default,
so every `docker compose up -d --build` kept baking in a URL that fails
outright now that Caddy serves plain HTTP only (auto_https off, nothing
on 443).

- README.md: VPS migration steps stopped telling people to set
  NEXT_PUBLIC_API_BASE_URL=https://osu.yourdomain.com (stale advice that
  reintroduces the exact bug #5 fixed); added an explicit upgrade note
  for exactly this stale-.env scenario with the one-line fix.
- frontend/.env.example: removed. It was unreferenced by any script or
  compose file (docker-compose.yml sources the root .env only) and still
  had the same stale https://osu.localhost default, so it was a dead file
  actively misleading anyone who copied it for local `pnpm dev`.

No application code changed - this closes the operational footgun that
caused the regression report, since the root .env.example is now the only
config source and already defaults to empty.
